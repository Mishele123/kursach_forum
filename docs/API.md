# API первого спринта

Базовый адрес при локальном запуске: `http://localhost:8000`.
Интерактивное описание схем и ответов: `/docs`, JSON-схема: `/openapi.json`.

## Сессии и подключение фронтенда

Используйте одинаковый hostname для фронтенда и API: например, `localhost` для обоих.
Браузерные запросы должны включать `credentials: 'include'`.
Разрешённые origins задаются JSON-массивом `WEB_ALLOWED_ORIGINS` в `.env`.
По умолчанию разрешены `http://localhost:5173` и `http://127.0.0.1:5173`.
Перезапустите сервер после изменения настроек. Не используйте `*` с cookie.

Вход устанавливает HttpOnly cookie `session_id`; JavaScript не должен читать её.
При `remember_me: false` cookie действует до завершения сессии браузера;
при `true` получает Max-Age. Срок серверной сессии задаёт `REDIS_SESSION_TTL_SECONDS`.
По HTTP используйте `WEB_COOKIE_SECURE=false`; для HTTPS — `true`.
Текущая SameSite=Lax конфигурация рассчитана на сайт и API в пределах одного site.

## Авторизация и профиль

| Метод | Путь | Результат |
| --- | --- | --- |
| POST | `/auth/register` | Создание пользователя, 201 |
| POST | `/auth/login` | Вход по email, 200 и cookie |
| GET | `/auth/me` | Текущий профиль, 200 |
| POST | `/auth/logout` | Удаление текущей сессии и cookie, 204 |
| GET | `/users/me` | Текущий профиль, 200 |
| PATCH | `/users/me` | Частичное изменение своего профиля, 200 |

Регистрация:

```json
{"username":"rider","email":"rider@example.com","password":"ExamplePassword123"}
```

Вход:

```json
{"email":"rider@example.com","password":"ExamplePassword123","remember_me":true}
```

Имя: 3–50 символов, латиница, цифры, `_`. Пароль: 8–128 символов.
Email и имя уникальны без учёта регистра. Несуществующий email и неверный пароль
возвращают 401. Повторная регистрация — 409, неверный формат — 422.
Email обязателен для новых регистраций. Старые пользователи с пустым email
сохраняются, но вход по имени больше не поддерживается; автоматического присвоения
email или подтверждения владения адресом нет.

Изменение профиля:

```json
{"city":"Самара","discipline":"MTB","interests":["маршруты","ремонт"],"bio":"Катаюсь по выходным"}
```

Пропущенные поля сохраняются. `null` очищает город, дисциплину или описание,
пустой список очищает интересы. Город и дисциплина — до 100 символов,
описание — до 2000, интересы — до 20 строк по 80 символов.
Роль, email, имя и чужой ID этим запросом менять нельзя.

## Посты и лента

| Метод | Путь | Результат |
| --- | --- | --- |
| POST | `/posts` | Создание текстового поста от текущего пользователя, 201 |
| GET | `/posts?limit=20&cursor=...` | Общая публичная лента, 200 |
| GET | `/posts/{id}` | Один публичный пост, 200 |
| PUT | `/posts/{id}/photo` | Загрузка или замена одной фотографии автором, 200 |

Создание поста:

```json
{"title":"Маршрут к озеру","text":"Описание поездки","category":"route"}
```

Заголовок: 1–200 символов, текст: 1–10000; пробельные значения запрещены.
Категории: `maintenance` — обслуживание, `upgrade` — апгрейд,
`route` — маршрут, `tricks` — трюки. Текст обычный, без HTML/редактора форматирования.
Фронтенд должен выводить его как текст, не через необработанный HTML.

В ответе: `id`, `author: {id, username}`, `title`, `text`, `category`,
`created_at`, `photo_url` (null, если фото нет). Email автора в ленту не попадает.
Автор берётся из сессии, передавать его ID не нужно.

Лента возвращает `{items: [...], next_cursor: "..."}`. Посты идут от новых к старым;
`limit` — от 1 до 100. Для следующей страницы передайте полученный `next_cursor`
как query-параметр с обычным URL-кодированием. `null` означает конец списка.

Для фотографии сначала создайте пост, затем отправьте multipart/form-data с полем
`file` на `/posts/{id}/photo`. При отправке FormData не задавайте Content-Type вручную.
Допустимы JPEG/PNG до 5 МиБ и 20 мегапикселей; содержимое проверяется и перекодируется
в JPEG без исходных метаданных. Новое фото заменяет предыдущее. Путь `/media/...`
в ответе относится к серверу API. Фотографии публичны, как и посты.
При ошибке фотографии текстовый пост остаётся; загрузку можно повторить.

Нет входа — 401, заблокированный пользователь или чужой пост — 403,
пост не найден — 404, слишком большой файл — 413, неподдерживаемый/повреждённый — 415.

## Велосипеды в профиле

`POST /users/me/bikes` создаёт велосипед (201):

```json
{"brand":"Trek","model":"Marlin","year":2024}
```

Бренд и модель: 1–100 символов. Год — целое число от 1800 до следующего
календарного года включительно (верхний технический предел 2200).
`GET /users/me/bikes` возвращает список своих велосипедов для отображения в профиле.
Владелец определяется по сессии; передать чужого владельца нельзя.

## Общие ошибки

Ошибки входных данных FastAPI возвращает с кодом 422. При отсутствии или
истечении сессии защищённые запросы возвращают 401. Поля ошибок представлены
`detail`, для существующих доменных ошибок также присутствует `error`.
Запрос изменения с неразрешённым заголовком Origin возвращает 403.

## Спринт 2 — поиск людей и публичный профиль (US1)

- `GET /users?city=Самара&discipline=MTB&brand=Trek&model=Marlin&limit=20`
  возвращает `{items: [...], next_cursor: ...}`. Все непустые фильтры применяются
  совместно; совпадение по подстроке без учёта регистра. Пробелы по краям удаляются,
  пустые фильтры игнорируются, `%` и `_` считаются обычными символами.
  Бренд и модель должны совпасть у одного велосипеда. Владелец выводится один раз.
- Порядок поиска — по ID пользователя по возрастанию. Передавайте `next_cursor`
  в параметре `cursor`, сохраняя фильтры; при смене фильтров сбрасывайте курсор.
  `limit`: 1–100, по умолчанию 20. `next_cursor: null` означает конец списка.
- `GET /users/{id}` возвращает публичные `id`, `username`, `city`, `discipline`,
  `interests`, `bikes`. Велосипеды содержат `id`, `brand`, `model`, `year`.
- `GET /users/{id}/posts?limit=20` возвращает публикации этого автора в формате
  ленты. Порядок — ID поста по убыванию. Передавайте полученный `next_cursor`
  только в этот endpoint для того же пользователя (курсор общей ленты отличается).
- Вход не требуется. Email, хеш пароля, сессии и служебные поля не выдаются.
  Удалённые пользователи не отображаются. Несуществующий/удалённый профиль — 404,
  неверные параметры — 422. Существующие `/users/me` и `/users/me/bikes` не меняются.

Страница поиска и ссылки на публичные профили во фронтенде этим изменением
не добавляются. Серверную часть можно проверить через Swagger `/docs`.

## Спринт 2 — серверный поиск публикаций (US2)

`GET /posts?q=озеро&category=route&limit=20` ищет во всей базе, до пагинации.
`q` — одна подстрока в заголовке ИЛИ тексте, без учёта регистра, до 200 символов.
Пробелы по краям удаляются, пустая строка отключает поиск; `%` и `_` — обычный текст.
Поиск по автору и разбивка запроса на отдельные слова не выполняются.
`category` — необязательный параметр: `maintenance`, `upgrade`, `route` или `tricks`;
неизвестная/пустая категория возвращает 422. Чтобы отключить фильтр, не передавайте её.
Поиск и категория применяются совместно. Ответ и курсор общей ленты не изменились:
`{items: [...], next_cursor: ...}`, новые публикации первыми, limit от 1 до 100.
Для следующей страницы передавайте тот же `q`, `category` и полученный `cursor`.
При смене условий начните без курсора. Пустая выдача: `items: []`, `next_cursor: null`.
Чтение публичное; посты удалённых пользователей исключены, как и в обычной ленте.
Фронтенд этим коммитом не меняется: подключение его поиска к этим параметрам —
отдельная задача фронтенд-разработчика. Проверка доступна в Swagger, GET /posts.

## Спринт 2 — комментарии (US3)

- `POST /posts/{id}/comments`, JSON `{"text":"Комментарий"}`: 201, нужна сессия.
  Автор определяется сервером; текст после удаления пробелов по краям — 1–3000 символов.
- `GET /posts/{id}/comments?limit=20&cursor=...`: публичный список, новые первыми.
  Ответ `{items: [...], next_cursor: number|null}`; limit 1–100.
  Комментарий содержит `id`, `post_id`, `author: {id, username}`, `text`, `created_at`.
- Нет сессии — 401, заблокирован автор комментария — 403, публикация не существует
  или принадлежит удалённому пользователю — 404, неверный текст/параметры — 422.
  Комментарии удалённых пользователей скрываются. При смене публикации курсор сбрасывается.
- На странице отдельного поста добавлен базовый блок с отправкой, подгрузкой,
  обработкой ошибок и приглашением войти для гостя. HTML из текста не исполняется.
- Нужна миграция `0006`; редактирование и удаление комментариев в этот шаг не входят.

## Спринт 2 — лайки (US4)

- `PUT /posts/{id}/like` ставит лайк текущего пользователя, `DELETE` по тому же
  пути снимает его. Тело не требуется. Нужна сессия; оба метода возвращают 200
  и `{post_id, like_count, liked_by_me}`. Повторение операции не меняет результат:
  повторный PUT не добавляет второй лайк, повторный DELETE не уменьшает счётчик.
- Уникальность пары пользователь/пост обеспечена БД. Одновременные изменения
  одного поста выполняются последовательно; счётчик отражает состояние в момент
  операции (другие пользователи могут изменить его позже).
- `like_count` и `liked_by_me` добавлены к постам общей ленты, поиска, отдельного
  поста и публикаций публичного профиля. Гостю/неактивной сессии возвращается
  `liked_by_me: false`; количество остаётся публичным. Лайки удалённых пользователей
  не учитываются. Персонализированные ответы имеют `Cache-Control: private, no-store`.
- Нет сессии — 401, заблокированный пользователь — 403, отсутствующий пост или
  удалённый автор поста — 404. Требуется миграция `0007`.
- Фронтенд не изменён: кнопку лайка нужно подключить отдельно. В браузере запросы
  должны передавать cookie; DELETE разрешён в настройках CORS.
