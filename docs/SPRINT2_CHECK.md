# Проверка бэкенда спринта 2

Сайт: http://localhost:5173. Swagger: http://localhost:8000/docs.

В Swagger раскрой метод, нажми **Try it out**, заполни поля и нажми **Execute**. Все действия выполняй на одном адресе `localhost:8000`: браузер автоматически сохранит cookie после входа. Авторизация на сайте и в Swagger использует cookie на одном hostname; не смешивай `localhost` и `127.0.0.1`.

Для проверки лучше зарегистрировать отдельный тестовый аккаунт через `POST /auth/register`: уникальные email и username, пароль не короче 8 символов. Затем выполнить `POST /auth/login` с email и паролем. `GET /auth/me` должен вернуть твой профиль. Реальные пароли не отправляй в чат и не сохраняй в репозитории.

## Что добавлено

| История | Реализовано на бэкенде | Как проверить |
|---|---|---|
| US1 | Поиск людей, сочетание фильтров, публичный профиль | `GET /users` с городом/дисциплиной/брендом/моделью; `GET /users/{id}` и `/users/{id}/posts`. Email в публичном профиле отсутствует. |
| US2 | Поиск постов по заголовку/тексту и категории во всей базе | `GET /posts` с `q`, `category`, небольшим `limit`; следующий запрос с возвращённым `next_cursor`. |
| US3 | Создание и чтение комментариев, пагинация | `POST /posts/{id}/comments` с `{"text":"Проверочный комментарий"}`, затем `GET` того же пути. Базовый блок комментариев также есть на сайте. |
| US4 | Постановка/снятие лайка, счётчик, состояние пользователя | Дважды `PUT /posts/{id}/like`: счётчик увеличивается только один раз. `DELETE` снимает лайк. Проверить `like_count` и `liked_by_me` в посте. |
| US5 | Фото велосипеда | Создать велосипед через `POST /users/me/bikes`, затем `PUT /users/me/bikes/{bike_id}/photo`, выбрать JPEG/PNG в поле `file`. Полученный `photo_url` открывается в браузере. |
| US6 | Аватар | `PUT /users/me/avatar`, поле `file`. Проверить `avatar_url` в `/auth/me`, публичном профиле, авторе поста/комментария. |
| US7 | Несколько фото публикации | `POST /posts/with-photos`, заполнить title/text/category и выбрать несколько файлов в `files`. Ответ содержит `photos` и первую фотографию в `photo_url`. Добавить ещё можно через `POST /posts/{id}/photos`. |
| US8 | Смена пароля | Инструкция ниже. |
| US9 | Смена имени | Инструкция ниже. |

Фотографии: JPEG/PNG до 5 МиБ и 20 мегапикселей каждая, до 10 фото на пост. Чужие фотографии менять нельзя. Если один файл партии неверный, партия целиком отклоняется. Старый `PUT /posts/{id}/photo` заменяет обложку, сохраняя остальные фото.

## US8 — пароль

1. Выполни `PUT /auth/password` с `current_password` и отличающимся `new_password` (8–128 символов). Успех: **204**, пустой ответ.
2. Выполни `POST /auth/logout`, затем `POST /auth/login` со старым паролем: **401**.
3. Войди с новым паролем: **200**.
4. Попробуй сменить пароль, указав неверный текущий: **400**. Новый короче 8 символов: **422**. После ошибки действующий пароль не меняется.

Существующие сессии сохраняются: смена пароля не выполняет выход со всех устройств.

## US9 — имя

1. Выполни `PATCH /users/me/username` с `{"username":"my_new_name"}`. Успех: **200**, профиль с новым именем.
2. Обнови `/auth/me`, публичный профиль и свой ранее созданный пост: имя автора должно обновиться, ID остаётся прежним.
3. Занятое другим пользователем имя (в том числе в другом регистре) даёт **409**. Имя короче 3 символов или с пробелом внутри — **422**. Разрешены 3–50 латинских букв, цифр и `_`.
4. Выйди и войди: email и пароль не меняются из-за смены имени.

## Интерфейс и автоматические проверки

Наличие API не означает, что все кнопки уже подключены на фронтенде. В этой ветке добавлен базовый блок комментариев; новые формы настройки профиля и галерею нужно подключить отдельно. В текущем nginx лимит запроса 6 МиБ — при подключении галереи увеличить до 51 МиБ. Напрямую через Swagger на порту 8000 этот лимит прокси не действует.

Из корня репозитория при работающем Docker:

```sh
.venv/bin/python tests/run.py
```

Проверки используют отдельную временную базу, отдельные ключи Redis и папку файлов. Данные сайта не очищаются. Проверяются миграции, права доступа, ошибки, повторные и одновременные запросы.
